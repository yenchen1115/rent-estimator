      About the model

      This follows the team's analysis. States are grouped into Low, Medium and High market segments by k-means on each state's median rent per sq ft, and each segment has its own random forest that predicts monthly price from bathrooms, bedrooms, square feet, state and the 27 amenities.

      SegmentStatesListings5-fold CV R²Median errorTree nodes
      • This page runs the team's final models unchanged: RandomForestRegressor(random_state=0) with default settings, 100 fully grown trees per segment, trained on all listings in the segment. The page downloads only the segment of the state you choose, once per visit.
      • The R² column is the 5-fold cross-validation score from the notebook, recomputed with the same code.
      • The 80% range comes from the cross-validated errors in each segment: 8 in 10 real rents fell inside it. It is wider in the High segment, where rents vary the most.
      • "What each amenity changes here" compares the estimate with and without that amenity for this specific unit. These are associations in the data, not the value an amenity adds.
      • The model was trained on asking rents posted between December 2018 and December 2019, about 94% of them on RentDigs.com.
      How the verdict and negotiation points work
      • Verdict: the listed rent is compared with the estimate and its 80% range. Below the range is a good deal; up to 3% above the estimate is a fair price; above that but inside the range leaves room to negotiate; above the range is more than the model expects.
      • Comparable listings: listings in the same state with the same number of bedrooms. When there are fewer than 20, the page uses all states in the same market segment instead, shown as "states with similar rent levels" since the segments group states by rent per square foot.
      • Missing amenities are listed when at least 25% of comparable listings mention them and adding them raises the model's estimate by at least $15 or 1%. Many listings don't mention every amenity, so these shares understate how common an amenity really is.
      • Dollar amounts for amenities, size and bathrooms are averages over up to 100 real listings with the same state and bedroom count: the model prices each of them with and without the feature, and the page reports the average difference. This is steadier than changing one feature on this unit alone, but it describes similar units in general rather than this unit exactly. When an amenity's or bathroom's amount is more than 5% of the estimate, the page doesn't show it: amenities such as a gym, and extra bathrooms, come mostly with newer, higher-end buildings in pricier areas, and the model, which only knows the state, can't separate them from the building.
      • Similar listings on the scale have the same number of bedrooms and a size within 20% of this unit, in the same city when there are at least 20 of them, otherwise in the same state or market segment.
      • Location compares the listed rent with the median rent of same-bedroom listings in the same city, for cities with at least 20 such listings. This comes from the data directly, because the model itself only uses the state. If you paste a listing site's city rent table (average rent by bedroom count, such as "How much does it cost to rent an apartment in New York?"), the comparison uses that table's average for the same bedroom count instead, as long as the city matches. Those averages are current, but they run above a typical rent because a few expensive units pull them up.
      • Move-in specials: free weeks and one-time discounts are spread over the lease to give the rent after specials, which is what the verdict uses.
      • Fees change the estimated total monthly cost and the cash needed at move-in, not the verdict, because the 2018–2019 listings don't say which fees their rent included. Fees are sorted by the headings on the listing (Required, One-Time, Situational, Add-Ons, Pets, Parking) and by name when there are no headings. Required fees always count, pets, parking and add-ons count when ticked, and situational fees such as transfer or month-to-month charges never count. One-time fees are spread over the lease; refundable deposits only add to the move-in cash.
      • Days on market: a listing that has been up for more than 14 days adds a negotiation point.
      • What to ask for depends on the verdict. Above the estimate, the list is titled "There is negotiable space on" and includes reasons to lower the rent, plus a counter-offer at the model estimate. At a fair price it becomes "Worth asking about" and keeps only fees and amenities to ask about, since arguing the rent down no longer makes sense. For a good deal or an unusually low rent it becomes "Before you sign" and keeps only things to confirm. Possible duplicate fees and costs that vary are listed in every case. Each list shows its five largest points.
      Bringing the estimate up to date

      RegionBLS series2019 averageLatestMultiplier
      • The model's 2019-price estimate is multiplied by the rent index growth of the listing's Census region. The model itself is unchanged.
      • This uses the rent index only. It already includes general inflation, so the all-items CPI is not applied on top.
      • The adjustment assumes every unit in a region grew at the region's average rate. States, cities and unit types within a region can differ.
      • The BLS index covers rents paid by all tenants, including existing leases, so it can rise more slowly than rents on new listings.
      Columns from the dataset that are not inputs
      • price, price_display: the value being predicted.
      • cityname, latitude, longitude, address: the team's model uses the state for location.
      • pets_allowed, has_photo, fee: not used in the team's model.
      • category, price_type, currency: the data covers monthly USD apartment rents only.
      • id, title, body, source, time: identifiers, free text and posting metadata.
      Updating the model

      Running train_team_rf_full.py rebuilds model.json (segments, states, scores and feature names) and the compressed tree files rf_high.txt, rf_medium.txt and rf_low.txt. Features follow the order scikit-learn's get_feature_names_out() gives them, such as cats__state_TX and remainder__square_feet, so a change to the notebook's features carries over when the files are rebuilt.
